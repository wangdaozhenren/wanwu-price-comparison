# 电商平台路由与注意点

按平台执行搜索时的入口、登录要求、页面结构与常见坑。数值与结构是经验基线，页面改版后以实际观察为准；每次采集前先观察页面再定位元素。

## 京东（默认推荐）

- 入口：`https://search.jd.com/Search?keyword=<URL编码关键词>`，或用搜索框输入后回车。
- 登录要求：**全新浏览器会话下搜索页可能直接跳转登录页**（`passport.jd.com`，实测发生）；登录后自动回到搜索结果。出现登录墙一律按移交规则让用户登录，不要尝试绕路。
- 页面结构：结果列表是商品卡片，含标题、价格（红色 `¥`）、店铺名、评价数。价格可能是"促销价"或"预约价"，注意区分。
- 排序：默认"综合"，可点"销量"排序获得更常见的规格；排序切换后重新读取。
- 口径提示：区分"京东自营"与"第三方店铺"，自营价和第三方价直接可比性更好；商品卡片标题含规格（如"整箱24罐"），注意与用户需求匹配。
- 常见坑：结果页可能弹出"登录有礼"等浮层，属被动 UI，直接忽略继续读取；若读取不到价格，先滚动触发懒加载。

## 1688（批发价，通常免登录）

- 入口：`https://s.1688.com/selloffer/offer_search.htm?keywords=<URL编码关键词>`，或站内搜索框输入提交。
- 登录要求：**新会话下搜索/查看完整价格常要求登录**（实测会跳转淘宝/1688 联合登录页），按登录移交规则处理，登录后回到搜索页继续。
- 搜索建议：**用站内搜索框直接输入中文关键词后点击"搜索"按钮提交**，不要手工拼接 URL 关键词——直接拼 URL 容易因编码（UTF-8/GBK 混用）导致乱码、搜出空结果（实测踩坑）。
- 页面结构：结果含标题、价格区间（如 `¥1.20-2.00`）、起批量（如"≥300件"）、成交笔数、公司名。
- 口径提示：1688 是**批发**平台——价格通常是含税未含运费、有起批量门槛。与京东/淘宝零售价比时必须在备注写"批发价+起批量"，不能直接当零售价比较。
- 常见坑：页面可能要求先登录才能看到完整价格区间；搜索词过长时结果少，可缩短关键词。

## 淘宝 / 天猫（需登录，走移交）

- 入口：淘宝 `https://s.taobao.com/search?q=<URL编码关键词>`；天猫 `https://list.tmall.com/search_product.htm?q=<URL编码关键词>`。
- 登录要求：网页端搜索基本强制登录/滑块验证。按登录移交规则处理：让用户在浏览器完成扫码/验证后交回，再重新读取。
- 页面结构：结果含标题、价格、月销量、店铺名、链接。注意"到手价"与划线价的区别，优先取到手价。
- 口径提示：淘宝有大量 C 店（个人店），与天猫旗舰店比价时注意店铺性质；同款商品不同店铺价差大，取前 5～10 条即可反映区间。
- 常见坑：滑块验证后若页面仍空白，先重载再读；登录态失效会跳回登录页，属登录墙，再次移交。

## 拼多多（风控严，常需登录）

- 入口：移动端 `https://mobile.yangkeduo.com/search_result.html?search_key=<URL编码关键词>`。
- 登录要求：网页端通常强制登录且风控严格，滑块/验证频繁。按登录移交规则处理；用户放弃时如实报告"拼多多本次未采集"，建议用户用 App 自查，并说明这是平台限制而非技能缺陷。
- 页面结构：移动端页面结果含标题、价格（常有"券后价"）、已拼件数、店铺。
- 口径提示：拼多多"百亿补贴/券后价"依赖登录态与领券，跨平台比较时备注价格口径。
- 常见坑：无登录态时常跳到登录页或验证页；页面 JS 较重，读取前等 `wait_for_load`。

## 其他可选平台

- **苏宁易购**：`https://search.suning.com/<关键词>/`，免登录可读，结构类似京东。
- **国美 / 当当 / 唯品会**：均可用站内搜索，免登录程度不一，按实际观察处理。
- **闲鱼**（二手）：`https://www.goofish.com/`，网页端常要求登录，且商品非标（二手、成色），仅当用户明确要二手比价时使用。

## 通用兜底

- **结果提取优先用 `bu.get_page_text()` 文本解析**：电商平台页面结构改版频繁，固定 CSS 选择器（如京东 `li.gl-item`）实测已失效返回空；先读整页文本再按"标题/¥价格/店铺/销量"字段切分，比依赖选择器稳定。
- 某平台页面打不开/被墙/风控拒绝：换该平台的移动端域名重试一次；仍失败则如实报告原因，不伪造价格、不拿别家价格冒充。
- 关键词建议同时试"商品名"与"商品名+规格"两种，避免搜索词过长导致结果偏少。
- 所有价格都记录"读取时点"，同一任务内尽量短时间完成，减少价格波动误差。
